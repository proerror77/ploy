## 1. 产品概述

### 1.1 产品是什么

Ploy 是一个面向预测市场（Prediction Markets）的自动化算法交易平台，当前主要接入 **Polymarket**（二元期权预测市场）。平台支持多策略并行运行、统一风控管理、以及基于历史数据的策略研究与回测。

### 1.2 核心价值主张

- **系统化套利与定价优势**：通过量化模型识别市场错误定价，在 Polymarket 上持续获取正期望收益
- **多策略协同**：同时运行方向性、套利、动量、信息优势等多类策略，分散单一策略风险
- **研究驱动迭代**：每次策略上线前经过严格回测验证，降低实盘亏损风险
- **运营安全**：多层风控 + 紧急停止机制，保障资金安全

### 1.3 目标市场

- **主市场**：Polymarket 加密货币二元期权（BTC/ETH/SOL/XRP/BNB/DOGE）
- **扩展市场**：Polymarket 体育赛事（NBA/NFL）、选举/监管事件
- **潜在扩展**：其他预测市场平台（Kalshi、Manifold 等）

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 描述 | 主要操作 |
|------|------|----------|
| **策略研究员** | 设计、回测、优化交易策略 | 运行回测、分析因子、调整参数 |
| **运营工程师** | 部署、监控、维护线上策略 | 部署策略、查看状态、处理告警 |
| **风控负责人** | 设置风险参数、审查异常 | 配置限额、触发熔断、审计日志 |

### 2.2 核心使用场景

**场景 A：新策略上线流程**
1. 研究员在历史数据上回测策略，验证正期望
2. 在 paper 模式（模拟盘）运行 1-2 周，观察行为
3. 通过 live 模式上线，初始小仓位
4. 运营工程师通过 CLI/TUI 监控运行状态

**场景 B：日常运营监控**
1. 运营工程师通过终端仪表盘查看所有策略实时状态
2. 收到告警时，通过 CLI 查看详情并决策（暂停/继续/停止）
3. 每日复盘 PnL、成交记录、风控触发情况

**场景 C：异常处理**
1. 策略触发熔断（日亏损超限）
2. 系统自动暂停该策略
3. 运营工程师审查原因，手动恢复或调整参数后重启

## 4. 非功能需求

### 4.1 性能

| 指标 | 当前目标 | 备注 |
|------|----------|------|
| 订单提交延迟 | < 500ms | 含网络往返 |
| 市场数据处理延迟 | < 100ms | 从接收到策略决策 |
| 系统可用性 | > 99.5% | 交易时段 |
| 崩溃恢复时间 | < 30秒 | 含状态恢复 |

### 4.2 可靠性

- 所有订单操作持久化到 PostgreSQL，支持崩溃恢复
- 死信队列（DLQ）处理失败订单，防止数据丢失
- 幂等性保护，防止重复下单
- 结算对账：定期与 Polymarket 官方状态比对

### 4.3 安全性

- Bearer Token 分级认证（管理员 / 操作员 / 边车）
- HMAC 签名会话 Cookie
- 请求频率限制
- 部署路径遍历保护
- 私钥/凭证通过 `secrecy` 库内存保护

### 4.4 可观测性

- 结构化日志（tracing）
- 审计日志（JSONL，所有控制面操作）
- 健康快照（定期持久化）
- 实时指标（Prometheus 兼容）
- 飞书告警推送

## 6. 优先级矩阵（近期 3-6 个月）

### P0 — 必须做（影响当前收益）

1. **修复 Binance 订单簿采集** — 微观结构特征是 PM5D V3 的核心依赖
2. **接入 AggTrades** — 动量信号完整性
3. **PM5D 微观结构特征层上线** — 提升策略胜率
4. **结算审计完成** — 确保 PnL 计算准确

### P1 — 重要（扩大收益边界）

5. **跨市场套利自动执行** — 新的 alpha 来源
6. **体育赛事实盘** — 扩大市场覆盖
7. **风控参数热更新** — 降低运营摩擦

### P2 — 有价值（提升运营效率）

8. **Web UI 完善** — 降低操作门槛
9. **策略参数自动优化** — 减少手动调参
10. **多主机部署** — 为规模化做准备

## 7. 成功指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 策略胜率 | 盈利交易 / 总交易 | > 55% |
| 夏普比率 | 年化收益 / 年化波动率 | > 1.5 |
| 最大回撤 | 峰值到谷值最大跌幅 | < 20% |
| 系统可用性 | 正常运行时间 / 总时间 | > 99.5% |
| 策略上线周期 | 从研究到实盘的时间 | < 2 周 |
| 熔断误触发率 | 非预期熔断 / 总熔断 | < 5% |

## 8. 术语表

| 术语 | 定义 |
|------|------|
| **Deployment** | 一个策略实例的运行配置，包含策略类型、账户、风控参数 |
| **Bundle** | 策略代码 + 配置的打包单元，对应一个 `.toml` 配置文件 |
| **Paper 模式** | 模拟盘，策略正常运行但不提交真实订单 |
| **Live 模式** | 实盘，策略提交真实订单到 Polymarket |
| **熔断** | 触发日亏损上限后自动暂停策略的机制 |
| **CLOB** | Central Limit Order Book，中央限价订单簿 |
| **IV** | Implied Volatility，隐含波动率 |
| **OBI** | Order Book Imbalance，订单簿不平衡度 |
| **DLQ** | Dead Letter Queue，死信队列，存放处理失败的消息 |
| **TUI** | Terminal User Interface，终端用户界面 |
